# 로그인 · Pro 이용권 설정 가이드

실모벅벅의 로그인(카카오·Google), 기록 동기화, EXP 횟수 관리, Pro 이용권 코드는 **Supabase** 한 곳에서 처리합니다.
코드는 이미 들어가 있고, 아래 설정을 마치고 anon 키를 `.env.production` 에 넣으면 켜집니다.
키를 넣기 전에는 로그인 버튼이 숨겨지고 사이트는 지금처럼 동작합니다.

> ⚠️ **service_role 키는 절대로 코드·채팅·깃허브에 올리지 마세요.** 사이트에 넣는 키는 `anon`(또는 `publishable`) 키 하나뿐입니다.

---

## 0. 프로젝트 정리 (한 번만)

1. Supabase 대시보드 → 프로젝트 → **Settings → General** → 이름을 `silbuk` 으로 바꾸기
2. **Organization → Team → Invite** → `silmobukbuk@gmail.com` 을 **Owner** 로 초대 (운영 계정으로도 관리 가능하게)
3. 무료 요금제는 **7일 동안 요청이 없으면 일시정지**됩니다. 사이트에 로그인 사용자가 생기면 자동으로 깨어 있지만,
   출시 전 테스트 기간에 멈췄다면 대시보드에서 **Restore** 를 누르면 됩니다.

## 1. 데이터베이스 만들기

1. 왼쪽 메뉴 **SQL Editor → New query**
2. 저장소의 `supabase/001_init.sql` 내용을 전부 복사해 붙여넣고 **Run**
3. "Success. No rows returned" 가 나오면 끝. (**Table Editor** 에 `profiles`, `entitlements`, `exam_results`, `pro_codes`, `code_redemptions` 가 보이면 정상)

## 2. 주소 설정

**Authentication → URL Configuration**

| 항목 | 값 |
| --- | --- |
| Site URL | `https://silbuk.com` |
| Redirect URLs | `https://silbuk.com/**` 와 `https://www.silbuk.com/**`, `http://localhost:5173/**` (각각 Add URL) |

## 3. Google 로그인

1. https://console.cloud.google.com → 상단에서 새 프로젝트 `silbuk` 만들기
2. **API 및 서비스 → OAuth 동의 화면**
   - 사용자 유형: **외부**, 앱 이름 `실모벅벅`, 지원 이메일 `silmobukbuk@gmail.com`
   - 승인된 도메인: `silbuk.com`, `supabase.co`
   - 범위: `email`, `profile`, `openid` (기본값)
   - 앱 홈페이지 `https://silbuk.com`, 개인정보처리방침 `https://silbuk.com/privacy.html`, 서비스 약관 `https://silbuk.com/terms.html`
   - 마지막에 **앱 게시(프로덕션으로 푸시)** — 테스트 상태로 두면 등록한 테스트 사용자만 로그인됩니다
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 유형: **웹 애플리케이션**
   - 승인된 JavaScript 원본: `https://silbuk.com`
   - 승인된 리디렉션 URI: `https://vcvljexputeugwuwtyeh.supabase.co/auth/v1/callback`
4. 나온 **클라이언트 ID / 클라이언트 보안 비밀번호**를 Supabase **Authentication → Sign In / Providers → Google** 에 붙여넣고 Enable → Save

## 4. 카카오 로그인

1. https://developers.kakao.com → 로그인 → **내 애플리케이션 → 애플리케이션 추가하기** (앱 이름 `실모벅벅`)
2. **앱 설정 → 플랫폼 → Web 플랫폼 등록**: `https://silbuk.com`
3. **제품 설정 → 카카오 로그인**
   - 활성화 설정 **ON**
   - Redirect URI: `https://vcvljexputeugwuwtyeh.supabase.co/auth/v1/callback`
4. **카카오 로그인 → 동의항목**
   - 닉네임: 필수 동의 / 프로필 사진: 선택 동의
   - 카카오계정(이메일)은 **비즈 앱**이어야 켤 수 있습니다. 개인 개발자도 [앱 설정 → 비즈니스 → 개인 개발자 비즈 앱 전환]으로 가능.
     전환이 번거로우면 이메일 없이 쓰고, Supabase 쪽에서 아래 옵션을 켜세요.
5. **앱 설정 → 앱 키**의 **REST API 키** 복사
6. **제품 설정 → 카카오 로그인 → 보안 → Client Secret** 코드 생성 → 활성화 상태 **사용함**
7. Supabase **Authentication → Sign In / Providers → Kakao**
   - REST API Key → `Client ID` 칸, Client Secret → `Client Secret` 칸
   - 이메일 동의항목을 안 켰다면 **Allow users without an email** 켜기
   - Enable → Save

## 5. 사이트에 키 넣기

1. Supabase **Project Settings → API Keys** 에서 **anon / publishable** 키 복사
2. 저장소 `.env.production` 의 `VITE_SUPABASE_ANON_KEY=` 뒤에 붙여넣고 커밋·푸시 (또는 Claude 에게 키를 주고 넣어달라고 하기)
   - anon 키는 원래 브라우저에 공개되는 키라 깃허브에 있어도 됩니다. 데이터는 RLS(행 단위 보안)로 본인 것만 보입니다.
3. 배포가 끝나면 사이트 오른쪽 위에 **로그인** 버튼이 생깁니다. 카카오·Google 각각 로그인 → [내 계정 · 설정]에 이름이 뜨면 성공

## 6. Pro 이용권 코드 만들기

SQL Editor 에서:

```sql
-- 30일권 10개, 코드당 1명
select * from public.create_pro_codes(10, 30, 1, '수능 끝 이벤트');

-- 7일권 1개를 100명까지 같이 쓰기 (SNS 공지용), 12월 31일까지 유효
select * from public.create_pro_codes(1, 7, 100, '인스타 공지', '2026-12-31 23:59+09');
```

나온 `SILBUK-XXXX-XXXX` 코드를 나눠주면, 받은 사람은 [내 계정 · 설정 → 이용권 코드]에 입력합니다.
사용 현황: `select * from public.pro_codes order by created_at desc;`

> 계좌 후원을 받고 코드를 주는 방식은 사실상 **판매**에 해당할 수 있습니다. 사업자 등록·세금 신고 여부를 먼저 확인한 뒤에 쓰세요.

## 7. 정식 오픈 (베타 종료)

`src/config/site.ts` 의 `betaFree: true` 를 `false` 로 바꾸고 배포하면:

| | 비회원 | 무료 회원 | Pro |
| --- | --- | --- | --- |
| 일반 타이머·채점 | ✅ | ✅ | ✅ |
| EXP 모드 | ❌ (로그인 안내) | 10회 (서버에서 차감) | 무제한 |
| 기록 동기화 | ❌ | ✅ | ✅ |
| 광고 | 있음 | 있음 | 없음 |

무료 횟수를 바꾸려면 SQL Editor 에서 `create or replace function public.exp_free_limit() returns int language sql immutable as $$ select 20 $$;`
처럼 숫자만 바꾸고, `src/lib/expQuota.ts` 의 `FREE_EXP_SESSIONS` 도 같이 맞춰주세요.

## 8. 결제 붙이기 (나중에)

- **웹**: 사업자 등록 후 토스페이먼츠 정기결제 → 결제 완료 웹훅에서 `entitlements.pro_until` 연장
- **앱(플레이 스토어)**: 디지털 상품은 Google Play 결제만 허용 → Play Billing 구독 → 서버 검증 후 같은 방식으로 연장
- 어느 쪽이든 앱 화면은 지금 구조(`get_entitlement`)를 그대로 쓰므로 화면 코드는 거의 바뀌지 않습니다.

## 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| 로그인 후 사이트로 안 돌아옴 / "redirect_to not allowed" | 2번 Redirect URLs |
| Google: "액세스 차단됨" | OAuth 동의 화면이 **테스트** 상태인지 → 앱 게시 |
| 카카오: KOE006 | 카카오 Redirect URI 가 Supabase callback 주소와 정확히 같은지 |
| 카카오: "Error getting user email" | Supabase Kakao 설정의 **Allow users without an email** |
| 로그인은 되는데 기록이 안 올라감 | 1번 SQL 을 실행했는지 (Table Editor 에 테이블이 있는지) |
| 갑자기 전부 안 됨 | 프로젝트가 일시정지(Paused) 됐는지 → Restore |
